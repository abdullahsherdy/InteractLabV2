Visual learning lab

Algorithms you can watch work

A complete UI/UX system for InteractLab — an interactive site that teaches data structures and algorithms to first-time programmers. The identity treats the whole site as an engineer's graph-paper notebook, where every structure is drawn, annotated, and animated live. These sheets define the foundations, the component kit, wireframes for every screen, and the prioritised upgrades that raise the current build to this standard.

S-01

Design principles

Six rules every screen is measured against. When choices conflict, the earlier rule wins.

01 · The diagram is the hero

Every page earns its keep by showing an idea moving, not describing it. The largest, most animated thing on screen is always the visualisation — copy supports it, never the reverse.

02 · Analogy before abstraction

A learner meets every concept first as an everyday picture (a chain of clues, a stack of plates), reused every time it returns. The formal term arrives second, once the picture holds.

03 · Technical, but warm

Crisp lines for what is drawn; soft edges for what is touched. Diagrams use thin ink strokes on graph paper; cards, buttons and copy stay rounded, roomy, and plainly worded so a beginner is never intimidated.

04 · One language, many inks

The paper, grid, ink text and red pencil never change. Each tool is simply drawn in its own accent ink — Linked Lists in green, Recursion in purple — so the site feels whole while every tool stays findable.

05 · Motion teaches, never decorates

Animation is reserved for showing change: a pointer moving, an array settling. Nothing loops for flourish. Every motion has an off switch (prefers-reduced-motion) and a manual replay.

06 · Nobody gets stuck

Full keyboard control, visible focus, 4.5:1 contrast, plain English, and no dead ends. No auto-grading and no week numbers — the mentor drives, the tool never judges.

Tool inks

Each tool keeps the accent it already ships with — now reframed as "the ink this sheet is drawn in." The paper stays the same; only the accent used for kickers, pointers, card icons and the module's diagram changes. This preserves wayfinding while unifying the identity.

S-05

Motion

Motion shows change and nothing else. One easing, three durations, always interruptible, always with an off switch.

Durations
fast · 140ms — hover, press
mid · 280ms — reveal, crossfade
draw · 520ms — arrow / node build
Easing
cubic-bezier(.22,1,.36,1)

One "ease-out" curve for everything that enters. Exits are faster than entrances. No bounce, no spring — this is a drafting table, not a toy.

Rules
  • ✓Reveal from a visible rest state, never opacity:0 forever
  • ✓Nothing loops except a true loader
  • ✓prefers-reduced-motion → jump to final frame
Signature moment

The one orchestrated sequence is the self-drawing schematic in the hero (see S-00): nodes fade up left-to-right, arrows extend by stroke-dashoffset, then red-pencil notes settle in. It runs once on load and on demand via a Replay the build control. Everywhere else, motion is a single micro-transition tied to a real state change.

S-08

Key flows

The three journeys the whole design serves. Each avoids dead ends and keeps the learner in control.

A · First visit

Land on home → the hero draws itself (proof, not promise) → scan 6 topic cards → open one → a one-time, skippable coach-mark: “Press play to watch it build.” → first module autoplays once.

B · Doing a lesson

Read analogy → press play / step with → → scrub back to re-watch a tricky step → flip the “bug” toggle to see it break → move to next Fig via the rail. Mentor narrates alongside.

C · On a phone

Chip bar shows module list → tap a Fig → diagram fills width (scrolls sideways with a fade cue) → transport is docked at the bottom, thumb-reachable → drawer to jump elsewhere.

S-10

Accessibility

WCAG 2.1 AA is the floor, not the ceiling — this audience needs it most. Verified against the ui/ux checklist.

Must hold on every screen
  • ✓Body text ≥ 4.5:1, large text ≥ 3:1 — ink on paper clears both in light & dark
  • ✓Every control keyboard-reachable, tab order = visual order, no traps
  • ✓Visible :focus-visible ring (red pencil, 2.5px) on all interactive parts
  • ✓State never by colour alone — pair with label, icon, or position
  • ✓SVG diagrams carry role="img" + a plain-English aria-label
  • ✓Sequential headings h1→h2→h3; one h1 per page
  • ✓Touch targets ≥ 44×44px; ≥ 8px apart
  • ✓prefers-reduced-motion jumps to the final frame, autoplay off

Language

Short sentences, common words, second person. Define a term the first time in the analogy. No idioms — the learner reads English as a second language.

S-12

Build roadmap

How this rolls into the live web/ app — tokens first, then shared parts, then per-tool, so nothing regresses.

Phase 1 · Foundations
Tokens & type

Replace the palette + fonts in globals.css / layout.tsx with the blueprint ground, tool inks, scale, radius, motion tokens. Graph-paper background utility. Ship behind the existing dark-mode structure.

Phase 2 · Shared kit
Header, cards, transport

Title-block header, drawn topic-card glyphs, the redesigned StepTransport (Step X/Y + scrubber + keyboard + aria-live), analogy field-note, code block, states. One place, reused everywhere.

Phase 3 · Home + one tool
Prove it in production

Rebuild the home hero (self-drawing schematic) and re-skin Linked Lists as the reference tool. Review on device, then confirm the pattern before rolling on.

Phase 4 · Roll out
Remaining tools + polish

Apply the ink-swap to Bitwise, Recursion, Sorting, Walkthroughs; build Stacks & Queues natively in the system. Then P2/P3 upgrades: coach-mark, skeletons, mobile drawer, refresh CLAUDE.md.

Non-negotiables carried forward

Client-only static export · analogy-before-abstraction · no week numbers · no auto-grading · pure tested logic in lib/ → SVG components → scoped CSS.
